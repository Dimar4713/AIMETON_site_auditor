# AIMETON SEF — Company Profile v1

**Статус:** исполняемый P0-контракт `SA-SEF-05`.

Company Profile v1 — детерминированная проекция `SefBundle` и
`LedgerSnapshot`. Профиль не извлекает факты заново и не просит LLM решить,
каким утверждениям доверять.

## Инварианты

1. `verified` всегда означает: claim прошёл Ledger, имеет
   `client_eligible=true` и ссылается на загруженное evidence.
2. Поисковые сниппеты не входят ни в поля, ни в приложение доказательств.
3. `hypothesis`, `not_found` и `blocked` видимы оператору, но не закрывают
   критические пробелы.
4. Финансовое значение без периода блокируется на уровне профиля, даже если
   исходный claim прошёл общий Ledger.
5. Неразрешённый conflict group делает `client_release_ready=false`.
6. Одинаковые bundle, snapshot и entity дают одинаковый профиль и ID.
7. Внешний API принимает Ledger request и пересчитывает snapshot сам; вызывающий
   код не может передать готовый флаг `client_eligible`.

## Четырнадцать секций

1. Идентичность.
2. Официальный сайт и домены.
3. Контакты.
4. Численность и кадровые сигналы.
5. Финансы и налоги.
6. Руководители и учредители.
7. Владельцы и аффилированность.
8. Суды, взыскания и банкротства.
9. Закупки, вакансии, новости и отзывы.
10. Бизнес-машина AIMETON.
11. Экономические сигналы.
12. AI-возможность и решения.
13. Риски, пробелы и противоречия.
14. Приложение доказательств.

## Шесть критических пробелов

- контакты;
- персонал;
- финансы;
- владельцы;
- аффилированность;
- правовые события.

Каждый пробел закрывается только хотя бы одним `verified` claim своего
домена. Для финансов дополнительно обязателен `period`.

## Evidence appendix

Приложение содержит только записи, связанные с profile fields:

- source и document;
- URL и дата загрузки;
- точная quote и locator;
- document/evidence digest;
- tier и freshness из Ledger;
- список связанных claim ID.

## API

`POST /api/sef/company-profile` принимает `bundle`, `ledger_request` и
`entity_id`, затем строит Ledger snapshot внутри доверенного контура.
При рассогласовании mission/correlation/entity возвращается `422`.

Успешный `profile_gate_passed` ещё не означает готовность к выдаче клиенту:
`client_release_ready` остаётся `false`, пока `SA-SEF-06` не добавит human
review и подписанную версию отчёта.
